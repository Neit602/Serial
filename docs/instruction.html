Portside

A serial terminal for Linux, macOS and Windows. It connects to routers, switches, embedded boards and lab equipment over USB-serial adapters, RS-232 ports and Bluetooth serial — with the same features and the same settings files on every operating system.

This guide explains what Portside can do and how to use its three faces: the desktop app portside-gui, the full-screen terminal UI that portside connect opens, and the plain command line portside.

What Portside does

Finds your adapters

Lists every serial port with its chip (FTDI, CP210x, CH340, PL2303…), USB ID and serial number, and refreshes within a second or two when you plug something in.

A real terminal

VT100/xterm emulation with colours, box drawing, full-screen programs, 10,000 lines of scrollback, search, copy and a hex view.

Break that always works

Sends a break to interrupt a boot and reach ROMMON — and emulates one when the adapter's driver cannot send a real break.

Pastes configs safely

Feeds a file to the device line by line, with delays or by waiting for the prompt, so slow network gear doesn't drop characters.

Records sessions

Logs as readable text with optional timestamps, or as the exact raw bytes, with automatic file names and size-based rotation.

Remembers devices

Profiles store all settings and attach to a physical adapter, so the right settings apply even when it shows up as a different port name.

Survives unplugging

When a device disappears, Portside waits for it and reconnects — even if it comes back as /dev/ttyUSB1 instead of /dev/ttyUSB0.

Explains errors

"Permission denied", "port busy" and "port not found" each come with the exact fix for your system, ready to copy.

Supported line settings: speed from 50 to 4,000,000 baud (any value, not just the common ones), 5–8 data bits, parity None/Even/Odd/Mark/Space, 1, 1.5 or 2 stop bits, and flow control None, RTS/CTS, DSR/DTR or XON/XOFF.

Installing

Portside is a Python package and needs Python 3.11 or newer. The desktop app uses Qt (PySide6) and the terminal UI uses Textual; both are optional extras, so install the ones you want. Run these commands in the Portside source folder. pipx keeps Portside in its own environment and puts the portside and portside-gui commands on your PATH.

Linux

pipx install ".[gui,tui]"      # or: pip install --user ".[gui,tui]"
portside --list

On Linux your user must be allowed to open serial devices. If Portside reports "permission denied" it shows the exact command; usually it is:

sudo usermod -aG dialout $USER    # "uucp" on Arch — then log out and back in

macOS

pipx install ".[gui,tui]"      # or: pip3 install --user ".[gui,tui]"
portside --list

Windows

py -m pip install --user ".[gui,tui]"
portside --list

Write ports plainly on the command line: COM12, not \\.\COM12.

On a server without a desktop, leave out gui: pipx install ".[tui]". The command line and the terminal UI never load Qt. If you install neither extra, connect with --raw — see Raw pass-through.

Quick start

  1. Plug in your USB-serial adapter and start Portside (portside-gui, or portside gui from a terminal).
  2. Your adapter appears in the Devices list on the left. Click it.
  3. Press Enter (or double-click it, or press Connect). A tab opens and you are connected at 115200 8N1.
  4. Press Enter in the terminal — the device's prompt should appear. If you see garbage instead, the speed is wrong: press Ctrl+, and choose the right baud rate (Cisco consoles use 9600).

Prefer the terminal? The same thing from the command line opens the terminal UI; F1 shows its keys and F10 quits:

portside --list
portside connect /dev/ttyUSB0 --baud 9600      # COM3 on Windows, /dev/cu.… on macOS

Connecting and managing sessions

  • Connect (Ctrl+N, Enter or double-click) uses the profile bound to that adapter if there is one, otherwise the defaults (115200 8N1, no flow control).
  • Connect with settings… (Ctrl+Shift+N) asks for the settings first.
  • You can have many sessions open at once, each in its own tab and completely independent.
  • File ▸ Detach tab to window moves a session into its own window without disconnecting it. File ▸ New Window (Ctrl+Shift+W) opens an empty one.
  • Disconnect (Ctrl+W) or the tab's × closes a session; Portside asks first if it is still connected.
  • If the cable is pulled, the status line shows reconnecting and Portside reconnects by itself when the same adapter returns — even under a different port name.

Working in the terminal

  • Typing: every key goes to the device, including Ctrl+C, Ctrl+Z, Tab, arrows and F-keys. What Enter and Backspace send is set per profile (CR and DEL by default).
  • Scrollback: mouse wheel, or PgUp/PgDn. New output does not pull you back down while you read; typing anything returns to the live output. The status line shows scrollback -N while you are scrolled up.
  • Copy: drag with the mouse to select, then Ctrl+Shift+C.
  • Find: Ctrl+F opens a search bar under the terminal. Matches are highlighted and counted; Enter or Next/Previous jump between them through the whole scrollback. The search is literal — you can type 10.0.0.1 or Gi1/0/1 without escaping anything.
  • Hex view: Ctrl+H shows the received bytes as a hex dump (offset, hex, ASCII) — useful for binary protocols and wrong-baud-rate noise.
  • Clear: Ctrl+K empties the screen and scrollback.
  • Themes: View ▸ Theme — Dark, Light or High contrast. Portside remembers your choice.

Sending a break

Press Ctrl+B (or Send break on the toolbar). This is what interrupts a Cisco or Juniper boot and drops it into ROMMON. The status bar reports what was sent:

  • native break, 250 ms — the adapter's driver produced a real break.
  • emulated break, 250 ms at 50 baud (2 zero bytes) — the driver cannot send a break, so Portside briefly switched to a very low speed and sent zero bytes, which the device sees as a break. Your line settings are restored immediately afterwards.

The break length and mode (automatic, native only, emulated only) are in Session settings ▸ Paste & break.

Pasting configurations

Press Ctrl+Shift+V and choose a file — or simply drag a file onto the window. Portside sends it line by line at the pace set in the profile, with a progress bar, and reports the result in the status line (e.g. sent 42/42 lines, 1290 B).

  • Delay per character and delay per line slow the paste down for devices that drop input.
  • Wait for prompt is the most reliable option: each next line is sent only after the device prints its prompt. For Cisco-style prompts use [>#]\s*$.
  • If the prompt never arrives within the timeout, the paste stops (or carries on, if you untick Stop the paste if the prompt never arrives).

Logging a session

Press Ctrl+L to start recording; the status bar shows where the file is, and the status line shows recording. Press it again to stop. To record every session automatically, tick Start logging when the session connects in the settings. See Log files for formats, names and locations.

Modem signals

The bottom-left panel shows the input lines, refreshed every second:

AppearanceMeaning
CTS green, boldThe line is asserted (high).
CTS greyThe line is low.
CTS pale, italicThis adapter's driver does not report the line at all — it is unknown, not low.

The DTR and RTS check boxes drive the output lines (both are on when a session opens). Some boards use them for reset or boot mode. If the driver has no such lines, the boxes grey out and their tooltip says why.

The terminal UI

portside connect <port> run in a terminal opens a full-screen terminal UI (it needs the tui extra). It is the same terminal as the desktop app — VT100/xterm emulation, 10,000 lines of scrollback, find, hex view, paced paste and logging — inside your SSH session or console window.

The line at the bottom shows the port, line settings, bytes in/out, the modem lines, REC and the file name while logging, scrollback -N while you are scrolled up, paste progress and the session state.

The command line

The portside program does everything without a window — useful over SSH, on lab servers and in scripts.

Listing ports

portside --list             # table of ports
portside --list --verbose   # adds the driver and stable path
portside --list --json      # for scripts

PORT          DESCRIPTION      VID:PID    CHIP         SERIAL
/dev/ttyUSB0  FT232R USB UART  0403:6001  FTDI FT232R  A50285BI
/dev/ttyS0    -                -          -            -

Connecting

portside connect /dev/ttyUSB0 --baud 115200
portside connect COM3 --baud 9600 --parity E --data-bits 7 --stop-bits 2
portside connect /dev/ttyUSB0 --profile cisco-lab        # use a saved profile
portside connect /dev/ttyUSB0 --reconnect                # wait for the device after a replug
portside connect /dev/ttyUSB0 --log session.log --timestamps elapsed

In an interactive terminal this opens the terminal UI. When input or output is piped, or with --raw, Portside uses raw pass-through instead.

Raw pass-through

In raw mode there is no terminal emulation: your own terminal window becomes the device's console, and the bytes you type go to the device exactly as typed. Device output goes to the screen (stdout); Portside's own messages, such as [portside] connected to …, go to stderr.

Press Ctrl+] to quit. Raw mode has no break or DTR/RTS keys — use the terminal UI or the desktop app for those.

Scripting

When input is piped, Portside forwards it byte-for-byte and ends when the input ends. Use it to send commands and capture replies:

printf 'show version\r' | portside connect /dev/ttyUSB0 --baud 9600 --quiet --drain 2 > version.txt
echo $?

Scripts can check the exit code:

CodeMeaning
0Success
1Other error
2Wrong options, or a missing or invalid profile
3Permission denied
4Port busy (open in another program)
5Port not found, or the device disappeared
For experiments without hardware, loop:// is a built-in test port that echoes back everything you send: portside connect loop://.

Profiles

A profile is a named set of all settings: line settings, Enter/Backspace behaviour, terminal options, paste pacing, logging and break. A profile can be bound to a physical adapter (by its USB ID and serial number); Portside then applies it automatically whenever that adapter is connected, whatever port name it gets.

In the desktop app

  • Edit ▸ Save session as profile… saves the current session's settings under a name and binds the profile to the connected adapter.
  • Edit ▸ Profiles… (Ctrl+P) lists your profiles. The one bound to the current device is marked (this device). Buttons: Edit, Bind to device, Duplicate, Delete, Export and Import (to share with colleagues).

From the command line

portside profiles                               # list
portside profiles show cisco-lab                # print it
portside profiles export cisco-lab --file cisco-lab.toml
portside profiles import cisco-lab.toml
portside profiles delete cisco-lab

Log files

Two formats:

  • Text — what you saw, decoded, one line per line with Unix (LF) line endings on every system, optionally with timestamps. Portside adds notes such as [portside] error: … or paste results.
  • Raw — the exact bytes received, unchanged — for protocol debugging.

Timestamps mark when each line started arriving:

[2026-10-16T14:03:07.250+02:00] Switch>     # absolute
[00:01:12.034] Switch>                     # elapsed since connect
[+00:00:00.412] Switch>                    # delta since the previous line

File names come from a template. The default is portside-{port}-{date}-{time}.log, giving names like portside-_dev_ttyUSB0-20261016-140307.log. Available placeholders: {port} (or {device}), {date}, {time}, {profile}, {n}. Characters that are not allowed in file names are replaced automatically.

With rotation enabled, a full file is renamed to name.1.log, name.2.log… and only the newest ones are kept. Restarting a log appends to the existing file rather than overwriting it.

SystemDefault log folder
Linux~/.local/state/Portside/log
macOS~/Library/Logs/Portside
Windows%LOCALAPPDATA%\Portside\Logs

A profile's [logging] directory, or the Folder field in the Logging settings, overrides the default folder.

Troubleshooting

When a port cannot be opened, Portside shows a dialog (or prints a message) with the fix for your system. In the desktop app, Copy fix puts the command on the clipboard.

"Permission denied" (Linux)

Your user is not in the group that owns the device. Portside names the right group — dialout on Debian/Ubuntu, uucp on Arch:

sudo usermod -aG dialout $USER     # then log out and back in

"Port is busy"

Another program has the port open — another terminal (minicom, screen, PuTTY, Arduino IDE), another Portside window, or on Linux often ModemManager. Close it and connect again. On Linux sudo fuser -v /dev/ttyUSB0 shows which program it is. On Windows, "access denied" almost always means the same thing.

The adapter is not in the list

  • Check the cable and try another USB port; the list refreshes by itself.
  • Windows: open Device Manager ▸ Ports (COM & LPT). A yellow warning sign means the driver is missing — CH340/CH341 adapters usually need the vendor's driver.
  • Ports that are not listed (e.g. Bluetooth /dev/rfcomm0) can still be used by typing their name: portside connect /dev/rfcomm0.

The screen shows garbage

The speed or framing is wrong. Common values: 9600 8N1 for Cisco and most network equipment, 115200 8N1 for development boards. Change it with Ctrl+, in the desktop app — the session stays connected. In the terminal UI, quit and reconnect with the right --baud. If text looks right but some characters are odd, try another character set (CP437 for old DOS-style boxes) or Strip the high bit.

Backspace or Enter don't work properly

Switch Backspace sends between DEL and BS, or Enter sends between CR and CR LF, in the Terminal settings. If you cannot see what you type, enable local echo.

The break does not reach ROMMON

Some drivers claim to send a break but don't. Set Break mode to Emulated only in Session settings ▸ Paste & break (or --break-mode emulated) and try again during boot.

macOS: where are the /dev/tty.* ports?

Portside lists only the /dev/cu.* ports. The matching /dev/tty.* ports wait for a carrier signal when opened and appear to hang, so they are hidden on purpose.

Pasted text is sent to the device exactly as configured. Before pasting a long configuration into production equipment, test the pacing settings on a lab device.
